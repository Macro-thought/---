## D1　2026-11-18　REFINE_TYPE 与 SPLIT_CONCEPT 的语义必须分开

**问题**：两个算子在初始实现里都只做「改 type、往 type_path 追加子类」，导致 SPLIT 在语义上是空操作——父类成员仍能解析到全部实例，计数与全称题一律不翻，与先验矩阵（拆分 → 全称必翻）不符。

**决策**：
- REFINE_TYPE：父概念保留，子类追加，成员解析按祖先闭包 → 细化**保指称**。
- SPLIT_CONCEPT：父概念废止，从 type_path 中移除，只留两个子类 → 父类成员集为空。

**依据**：「细化」是给已有概念加下级分类，「拆分」是把一个概念换成两个新概念。前者父类仍指称原集合，后者父类不再直接指称任何实例。这是两种不同的本体操作，不能共用一个实现。

**影响**：拆分后的全称题因空域而空真（vacuous truth），这正是先验矩阵 SPLIT × 全称 = 必翻 的来源。实测 8/8 翻转。论文必须写明这一点，否则会被质疑是求解器伪影。

## D2　2026-11-18　类成员解析采用「祖先闭包 + 叶子属性」

**问题**：若只按 `type` 精确匹配，细化后子类实例会从父类计数中消失，REFINE × 计数会翻转，与先验（稳定）冲突。

**决策**：`members(T)` = `type == T` 或 `T ∈ type_path` 或 `T ∈ {p31_subtype, airport_class, aircraft_class}`。

**依据**：v1 图把叶子分类存为节点属性（Wikidata 的 P31 本来就允许多值），查询系统没有理由看不见它。按此语义，细化只改呈现、不改指称。

**影响**：REFINE 三格实测全稳定（0%），与先验一致；SPLIT 的父类成员归零，实测翻转。

## D3　2026-11-18　MERGE 的同指实体对与属性继承

**选定**：保留 Q5099568（华航集团，企业），吸收 Q51756（中华航空，航空公司）。依据是 Wikidata P460「said to be the same as」同指关系。

**决策**：合并时只继承事实性属性（country / inception / hq），**不继承类型标签属性**（p31_subtype 等）。

**原因**：若把 `p31_subtype=航空公司` 抄到集团节点上，集团会被类解析当成航司，`members(航空公司)` 仍是 185，合并对计数完全无效——实测第一版 8 道计数题只翻 1 道。修掉属性继承后 8/8 翻转。

**影响**：MERGE × 计数实测 100% 翻转；MERGE × 指称因别名并入而稳定（「中华航空」仍解析到集团节点，枢纽机场答案不变）；MERGE × 全称 2/8 翻转（「华航集团」原本没有子公司，全称空真；合并后有了 7 家，且并非全是航司/都有枢纽）。

## D6　2026-11-18　求解器的空域语义

**决策**：全称题在空域上返回真（vacuous truth），与一阶逻辑一致。

**风险**：这会让 SPLIT 的全称格 100% 翻转显然是设计出来的。论文里必须把它写成「拆分导致父概念实例集为空，按经典语义全称为真」的事实，而不是「系统答错了」。也正因如此，FR 高不代表系统差——诊断的是**语义漂移**。

## D8　2026-11-18　基线阅读器的口径

**决策**：三个基线共用 `baselines/common.py:read_answer`，这是**抽取式占位阅读器**，不是 LLM。它只做三件事：计数题数可见实体、全称题查「并非/没有」、指称题抄关系句尾的实体名。B2/B3 在 context 是三元组时启用 `triple_mode`，把关系句限定为「问句主语的关系是…」，避免把邻域里别人的枢纽机场也算进来。

**理由**：没有 key 的情况下，任何“像 LLM 一样作答”的写法都是伪造。占位器的作用是证明检索→上下文→答案的管线通了，同时把所有未实现的能力暴露在台面上：计数题恒答 0，全称题近乎恒答“是”。

**后果**：`eval/scores.md` 里的 FR/FFR/MFR 只能当管线证据，不能当鲁棒性结论。接口已留：把 `read_answer` 换成一次 API 调用即可，检索与评测代码不动。

## D9　2026-11-18　B3 LightRAG 的处理

**探测结果**：`lightrag` 未安装，四个常见 key 环境变量均为空，`b3_status.json` 记 `available: false`。

**决策**：不 pip 安装、不伪造 LightRAG 数字。另提供 `--proxy` 模式，用「B1 文本块 + B2 2-hop 三元组」的本地混合检索顶替第三列，文件名、`system` 字段、`meta.warning` 三处都标注 proxy。

**复现条件**：装 `lightrag` 并导出任一 key 后，去掉 `--proxy` 重跑同一脚本；`probe()` 会自动翻成 `available: true`，届时再补真实三列对照。
